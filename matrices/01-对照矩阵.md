## 矩阵一：八大失效 × 八大机制

**读法**：行 = 失效形态，列 = 解决机制。★★★ = 主要解决，★★ = 重要辅助，· = 间接影响。

```
                    四相   工具   进度   上下文  任务   验证   子代理  GAN    Token
                    循环   编排   跟踪   工程    拆解   循环   分治   三角色  预算
                    ────  ────  ────  ──────  ────  ────  ────  ──────  ────
① 循环失控          ★★★    ·     ·      ·      ·     ·      ·      ·      ★★
   (无限循环)

② Context 溢出      ·     ·     ·     ★★★    ★★★    ·     ★★★    ·      ★★
   (窗口爆炸)

③ Cache Miss        ·     ·     ·     ★★★    ·      ·      ·      ·      ·
   (缓存不命中)

④ Tool 错误吞并     ·    ★★★    ·      ·      ·    ★★★    ·      ·      ·
   (异常被吞)

⑤ 状态丢失          ·     ·    ★★★    ★★     ·      ·      ·      ·      ·
   (Crash 归零)

⑥ 缺权限闸          ·    ★★★    ·      ·      ·      ·      ·     ★★     ·
   (越权操作)

⑦ 缺自动化评审       ·     ·     ·      ·      ·    ★★★    ·     ★★★     ·
   (没人检查)

⑧ 成本失控          ·     ·     ·     ★★★    ·      ·      ·      ·     ★★★
   (账单爆炸)
```

### 关键模式

**三道防线防 Context 溢出**：
```
第一道: 任务拆解 → 从源头减少 context 负担
第二道: 子代理分治 → 隔离独立任务，保护主 context
第三道: 上下文工程 → 压缩/重置，兜底保障
```

**两层防线防 Tool 错误**：
```
第一层: 工具编排 (工程层) → 结构化错误，Agent 能看见
第二层: 验证循环 (任务层) → 真机验证，Agent 能确认
```

**双重评审**：
```
验证循环: 微观自动评审（每步：pytest, lint, compile）
GAN 三角色: 宏观综合评审（整体：多维度打分，多方制衡）
```

## 矩阵二：八大机制 × 三支柱

**读法**：行 = 机制，列 = 所属支柱。★★★ = 核心所在支柱，★★ = 重要贡献，★ = 辅助贡献。

```
                    输入流   控制流   状态流
                    ──────  ──────  ──────
四相循环               ·      ★★★     ★★
  (执行节律)                 节奏控制  防止无限

工具编排               ★★     ★★★      ·
  (调用安全)         返回内容  调用权限

进度跟踪              ★★★      ·      ★★★
  (断点续传)         恢复上下文          持久化

上下文工程             ★★★      ·      ★★★
  (窗口管理)         看什么            压缩重置

任务拆解              ★★★     ★★       ★
  (化整为零)         聚焦视野  分步约束  减负

验证循环               ★      ★★★      ★
  (真机验证)         验证结果  判定流程  失败分支

子代理分治            ★★★     ★★      ★★★
  (隔离执行)         隔离视野  分治管控  独立生命

GAN 三角色              ★      ★★★      ★★
  (多方博弈)         评审输入  多方制衡  退回重试
```

### 关键模式

```
输入流重型 (Input-heavy):
  上下文工程 ★★★ + 任务拆解 ★★★ + 子代理分治 ★★★
  → 这三个机制主要解决"Agent 能看见什么"的问题

控制流重型 (Control-heavy):
  四相循环 ★★★ + 工具编排 ★★★ + 验证循环 ★★★ + GAN 三角色 ★★★
  → 这四个机制主要解决"Agent 能做什么/不能做什么"的问题

状态流重型 (State-heavy):
  进度跟踪 ★★★ + 上下文工程 ★★★ + 子代理分治 ★★★
  → 这三个机制主要解决"Agent 能跑多久"的问题
```

## 使用指南

### 当你遇到一个问题时

1. 打开 **矩阵一**：找到对应的失效形态
2. 查看该行的 ★★★ → 这是主要解决方案
3. 查看该行的 ★★ → 这些是辅助方案
4. 去对应的机制文档了解具体实现

### 当你在设计一个 Harness 时

1. 打开 **矩阵二**：确认你需要加强哪个支柱
2. 查看该列的 ★★★ → 这些是核心机制
3. 确保这些机制在你的设计中都被覆盖了

### 当你在评估一个 Agent 产品时

1. 打开 **矩阵三**：查看该产品在各机制的覆盖度
2. 重点关注你的场景最需要哪些机制
3. 缺的机制是否可以通过配置/插件弥补
