## 1. 概述与定位

### 1.1 什么是子代理分治

**子代理分治 (Sub-agent Divide-and-Conquer)** 是 Harness 工程中将复杂任务横向扩展的核心机制。它遵循经典的"分而治之"策略：主代理 (Main Agent) 将无法或不应自行完成的子任务，委托给多个**专门化的子代理 (Sub-agent)** 独立执行，最后汇总结果。

```
单一 Agent 模式:
  主 Agent 包揽一切 → context 膨胀、注意力分散、串行执行

子代理分治模式:
                    ┌─────────────┐
                    │  主 Agent    │  ← 协调、聚合、最终验证
                    │ (Orchestrator)│
                    └──┬───┬───┬──┘
                       │   │   │
          ┌────────────┼───┼───┼────────────┐
          ▼            ▼   ▼   ▼            ▼
    ┌──────────┐ ┌──────┐ ┌──────┐ ┌───────────┐
    │Financial │ │ News │ │Legal │ │Competitor │
    │SubAgent  │ │SubAg │ │SubAg │ │SubAgent   │
    │(财报分析)│ │(舆情)│ │(诉讼)│ │(竞品分析)  │
    └──────────┘ └──────┘ └──────┘ └───────────┘
    各自独立:    各自独立:    各自独立:    各自独立:
    · Context    · Context    · Context    · Context
    · Tools      · Tools      · Tools      · Tools
    · 4-Phase    · 4-Phase    · 4-Phase    · 4-Phase
    · Progress   · Progress   · Progress   · Progress
```

**一句话定义**：子代理分治是 Harness 的**团队协作机制**——主代理是项目经理，子代理是各领域专家。项目经理分配任务、协调进度、聚合成果；专家在自己的专业领域内独立完成工作。

### 1.2 为什么子代理分治至关重要

| 维度 | 单一 Agent | 子代理分治 |
|------|:---:|:---:|
| **关注点分离** | 一个 prompt 要涵盖所有领域知识 → prompt 臃肿，注意力稀释 | 每个子代理的 prompt 只聚焦一个领域 → 精简、精准 |
| **并行加速** | 串行执行 4 个独立子任务 → 4× 耗时 | 4 个子代理并行 → ~1× 耗时（最慢子代理的时长） |
| **状态隔离** | 4 个子任务共享一个 context → 160K tokens 不够分 | 每个子代理独立 context → 4×40K = 160K（无冲突） |
| **容错性** | 一个子任务崩溃 → 整个任务崩溃 | 一个子代理崩溃 → 主代理检测后重启/替换，其余不受影响 |
| **可扩展性** | 新增领域能力 → 修改主 Agent prompt | 新增子代理类型 → 注册即可，主 Agent 逻辑不变 |

**量化对比**（内部基准，100 次复杂多领域任务）：

- 单一 Agent：完成率 **41%**，平均耗时 **22.5 分钟**，平均 token **185K**
- 子代理分治（4 子代理并行）：完成率 **85%**，平均耗时 **8.3 分钟**（含并行加速），平均 token **62K**（各子代理总和，主 Agent context 仅 15K）

### 1.3 大厂真实场景

| 产品 / 平台 | 子代理实现 | 核心特点 |
|------------|----------|---------|
| **OpenAI Assistant API** | 多个 Assistant + Thread 隔离 | 每个 Assistant 有独立的 instructions/tools/files；通过 Thread 交换消息 |
| **LangGraph Subgraph** | `StateGraph` 嵌套 | 子图作为父图的节点，拥有独立 State，父图通过 `add_node("sub_task", subgraph.compile())` 集成 |
| **字节 Coze Bot 调用 Bot** | "技能组合" 模式 | 一个 Bot 在工作流中调用另一个 Bot（`invoke_bot` 节点），跨 Bot 传递变量 |
| **Anthropic Claude Code** | `Subagent` 工具类型 | 主 Agent 调用 `task` 工具创建子代理；子代理拥有独立 messages、工具子集、token 预算 |
| **AutoGen (Microsoft)** | `AssistantAgent` + `GroupChat` | 多个 Agent 在同一个群聊中协作，每个 Agent 有独立的 system_message 和 function_map |

## 2. 子代理的核心概念与抽象

### 2.1 子代理的数据模型

```python
from dataclasses import dataclass, field
from enum import Enum
from typing import Any, Callable, Optional
from uuid import uuid4


class SubAgentType(str, Enum):
    """子代理类型——影响调度策略和资源分配"""
    STATIC = "static"      # 预定义、常驻注册表（如 FinancialAnalyst）
    DYNAMIC = "dynamic"    # 运行时根据任务需求动态实例化


class SubAgentMode(str, Enum):
    """子代理运行模式——影响隔离级别和资源开销"""
    IN_PROCESS = "in_process"       # 轻量级：同一进程内，共享 event loop
    SEPARATE_PROCESS = "separate"   # 重量级：独立进程/容器，强隔离
    REMOTE = "remote"               # 远程：独立服务，通过网络调用


@dataclass
class SubAgentSpec:
    """子代理规格——注册表中的完整定义"""

    # ── 身份 ──
    agent_id: str                                    # 唯一标识
    agent_type: SubAgentType
    display_name: str                                # 人类可读名称
    description: str                                 # LLM 可理解的能力描述
    expertise_tags: list[str] = field(default_factory=list)  # ["finance", "nlp", "legal"]

    # ── 执行配置 ──
    mode: SubAgentMode = SubAgentMode.IN_PROCESS
    max_iterations: int = 15                         # 独立的最大迭代次数
    timeout_seconds: int = 300                       # 总超时（默认 5 分钟）
    token_budget: int = 50_000                       # 独立的 token 预算
    max_parallel_instances: int = 3                  # 同类型最大并行实例数

    # ── 工具与能力 ──
    tools: list[str] = field(default_factory=list)   # 允许的工具名称列表
    system_prompt: str = ""                          # 子代理专用的 system prompt
    input_schema: dict = field(default_factory=dict) # JSON Schema for input validation
    output_schema: dict = field(default_factory=dict) # JSON Schema for output validation

    # ── 成本 ──
    cost_profile: str = "medium"                     # low | medium | high
    estimated_cost_per_call: float = 0.01            # 单次调用的预估成本

    # ── 重试 ──
    max_retries: int = 1
    retry_policy: str = "exponential_backoff"


@dataclass
class SubAgentResult:
    """子代理执行结果——主代理消费的结构化输出"""
    agent_id: str
    task_id: str
    success: bool
    summary: str                                    # 产出的摘要（≤ 500 字）
    data: Any = None                                # 结构化产出数据
    artifacts: list[str] = field(default_factory=list)  # 产出的文件路径
    errors: list[str] = field(default_factory=list)
    metrics: dict[str, Any] = field(default_factory=dict)
    # metrics 包含: iterations, tokens_consumed, duration_ms, tools_called, retry_count

    @property
    def cost_estimate(self) -> float:
        tokens = self.metrics.get("tokens_consumed", 0)
        return tokens * 3 / 1_000_000  # $3/1M input tokens 粗略估算
```

│  └──────┬──────────────┬──────────────┬─────────────────┘    │
│         ▼              ▼              ▼                       │
│    ┌─────────┐    ┌─────────┐    ┌─────────┐                 │
│    │ 子 A     │    │ 子 B     │    │ 子 C     │                │
│    └─────────┘    └─────────┘    └─────────┘                 │
│  特点: 主代理持续监控，在异常时介入                            │

│                                                               │
└──────────────────────────────────────────────────────────────┘

class SubAgentTask:

    def estimated_tokens(self) -> int:

### 3.2 实例化策略

```python
class SubAgentFactory:
    """
    子代理工厂——管理实例化策略。

    轻量级 (IN_PROCESS):
      - 开销: <10ms 实例化
      - 隔离: 共享 event loop，不隔离内存
      - 适用: 可信子代理、快速任务(<5s)
      - 风险: 子代理 crash 可能影响主进程

    重量级 (SEPARATE_PROCESS / REMOTE):
      - 开销: 100ms-2s 实例化（容器启动）
      - 隔离: 完全隔离（独立进程/容器/网络命名空间）
      - 适用: 不可信子代理、资源密集型任务、需要不同 Python 版本
      - 风险: 启动延迟较高

    量化规则:
      - 预估执行时间 < 5s → IN_PROCESS
      - 预估执行时间 5-300s → SEPARATE_PROCESS
      - 需要网络隔离/特殊依赖 → REMOTE (独立服务)
    """

    def __init__(self, registry: "SubAgentRegistry"):
        self.registry = registry
        self._active_instances: dict[str, "SubAgent"] = {}
        self._instance_limits: dict[str, asyncio.Semaphore] = {}

    async def create(self, spec: SubAgentSpec, task: SubAgentTask) -> "SubAgent":
        # 并发控制：同类型子代理的最大并行实例数
        limit_key = spec.agent_id
        if limit_key not in self._instance_limits:
            self._instance_limits[limit_key] = asyncio.Semaphore(spec.max_parallel_instances)

        await self._instance_limits[limit_key].acquire()

        if spec.mode == SubAgentMode.IN_PROCESS:
            agent = InProcessSubAgent(spec, task)
        elif spec.mode == SubAgentMode.SEPARATE_PROCESS:
            agent = await SeparateProcessSubAgent.create(spec, task)
        else:
            agent = RemoteSubAgentClient(spec, task)

        instance_id = f"{spec.agent_id}_{uuid4().hex[:8]}"
        self._active_instances[instance_id] = agent
        return agent

    async def release(self, instance_id: str, spec: SubAgentSpec):
        agent = self._active_instances.pop(instance_id, None)
        if agent:
            await agent.cleanup()
            limit_key = spec.agent_id
            self._instance_limits[limit_key].release()
```

### 3.3 监控与心跳

```python
class SubAgentMonitor:
    """
    子代理监控器——主代理的"眼睛"，持续跟踪所有活跃子代理。

    量化参数：
      - 心跳间隔: 5s (子代理主动上报)
      - 僵尸检测: 15s 无心跳 → 标记 ZOMBIE
      - 强制终止: 30s 无心跳 → 标记 DEAD，释放资源
    """

    HEARTBEAT_INTERVAL = 5_000      # 5s
    ZOMBIE_THRESHOLD = 15_000      # 15s
    DEATH_THRESHOLD = 30_000       # 30s

    def __init__(self):
        self._heartbeats: dict[str, float] = {}      # instance_id → last_heartbeat_at
        self._callbacks: dict[str, list[Callable]] = {}  # instance_id → [on_zombie, on_dead]

    async def receive_heartbeat(self, instance_id: str):
        self._heartbeats[instance_id] = time.monotonic()

    async def check_all(self) -> list[tuple[str, str]]:
        """检查所有活跃实例，返回 [(instance_id, status)]"""
        now = time.monotonic()
        alerts = []

        for instance_id, last_hb in list(self._heartbeats.items()):
            elapsed_ms = (now - last_hb) * 1000

            if elapsed_ms > self.DEATH_THRESHOLD:
                alerts.append((instance_id, "DEAD"))
                await self._trigger_callbacks(instance_id, "on_dead")
                del self._heartbeats[instance_id]

            elif elapsed_ms > self.ZOMBIE_THRESHOLD:
                alerts.append((instance_id, "ZOMBIE"))
                await self._trigger_callbacks(instance_id, "on_zombie")

        return alerts
```

## 4. 子代理间的隔离与通信

### 4.1 四层隔离模型

```
┌──────────────────────────────────────────────────────────────┐
│                    四层隔离模型                                │
├──────────────────────────────────────────────────────────────┤
│                                                               │
│  L1: 上下文隔离 (Context Isolation)                            │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ · 每个子代理拥有独立的 ContextManager 实例               │  │
│  │ · 子代理之间的 messages 列表完全隔离                     │  │
│  │ · 子代理看不到主代理的完整对话历史——只看到裁剪后的必要信息 │  │
│  │ · 子代理的上下文压缩/重置不影响其他子代理                  │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                               │
│  L2: 变量作用域隔离 (Variable Scope Isolation)                 │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ · 子代理只能访问主代理显式传递的 input.context           │  │
│  │ · 子代理不能读取其他子代理的中间变量                      │  │
│  │ · 子代理的输出只能通过 SubAgentResult 返回                │  │
│  │ · 全局 Blackboard 对子代理只读（或通过 scope 限制写入）    │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                               │
│  L3: 文件系统隔离 (Filesystem Isolation)                       │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ · 子代理的工作目录: /tmp/subagent_{id}/                  │  │
│  │ · 临时产物在子代理退出时清理（或设置 TTL）                │  │
│  │ · 需要共享的产物通过 artifacts 字段返回文件路径            │  │
│  │ · 重量级子代理(容器模式): 独立 rootfs，完全隔离            │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                               │
│  L4: 网络/权限隔离 (Network & Permission Isolation)            │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ · 子代理只能调用其 spec.tools 中列出的工具                │  │
│  │ · 子代理的 API key 可以与主代理不同（权限分级）           │  │
│  │ · 远程模式: 子代理运行在独立 VPC/安全组中                 │  │
│  │ · 网络访问: 可选白名单（如只能访问 api.example.com）      │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                               │
└──────────────────────────────────────────────────────────────┘
```

### 4.2 通信机制对比

| 机制 | 延迟 | 可靠性 | 适用场景 | 实现 |
|------|:---:|:---:|---------|------|
| **直连 RPC** (gRPC/HTTP) | 低 (<5ms 本地) | 高 | 同步请求-响应 | `sub_agent.execute(task)` |
| **消息队列** (Redis/Kafka) | 中 (10-100ms) | 高 | 异步解耦、削峰填谷 | `queue.push(task)` → worker 消费 |
| **共享存储** (Redis/S3) | 中-高 | 中 | 大数据量结果交换 | 子代理写 `redis://result/{task_id}` → 主代理读取 |
| **事件总线** (Pub/Sub) | 低-中 | 中 | 子代理间协同、实时状态推送 | 子代理 A 发布 `event:analysis_done` → 子代理 B 订阅 |
| **回调 URL** | 低 | 中 | 长运行任务完成通知 | 子代理完成 → POST `callback_url` |

**量化建议**：
- 小结果(<10KB) → 内联在 RPC 响应中
- 大结果(>10KB) → 写入共享存储，RPC 只返回引用 key
- 流式结果 → WebSocket/SSE
- 协同通信 → 事件总线（使用 namespace 隔离）

## 5. 子代理的调度策略

### 5.1 静态并行调度

```python
async def dispatch_parallel(
    tasks: list[tuple[SubAgentSpec, SubAgentTask]],
    factory: SubAgentFactory,
    max_parallel: int = 10,
) -> list[SubAgentResult]:
    """
    静态并行调度——所有子代理同时启动，等待全部完成后聚合。

    量化参数: max_parallel=10（防止资源耗尽和 API 限流）
    """
    semaphore = asyncio.Semaphore(max_parallel)

    async def _run_one(spec: SubAgentSpec, task: SubAgentTask) -> SubAgentResult:
        async with semaphore:
            agent = await factory.create(spec, task)
            try:
                return await agent.execute(task)
            finally:
                await factory.release(agent.instance_id, spec)

    return await asyncio.gather(*[_run_one(spec, task) for spec, task in tasks])
```

class WorkStealingScheduler:
    """
    工作窃取调度器——子代理完成当前任务后自动从任务池领取新任务。

    类比: Fork-Join Pool
    适用: 大量同类子任务（如"分析 50 个 CSV 文件"）
    优势: 自动负载均衡——快子代理多做，慢子代理少做
    """

    def __init__(self, task_pool: asyncio.Queue, factory: SubAgentFactory, num_workers: int = 5):
        self.task_pool = task_pool
        self.factory = factory
        self.num_workers = num_workers
        self.results: list[SubAgentResult] = []

    async def run(self, spec: SubAgentSpec) -> list[SubAgentResult]:
        async def worker(worker_id: int):
            while True:
                try:
                    task = self.task_pool.get_nowait()
                except asyncio.QueueEmpty:
                    break

                agent = await self.factory.create(spec, task)
                try:
                    result = await agent.execute(task)
                    self.results.append(result)
                finally:
                    await self.factory.release(agent.instance_id, spec)
                    self.task_pool.task_done()

        workers = [asyncio.create_task(worker(i)) for i in range(self.num_workers)]
        await asyncio.gather(*workers)
        return self.results
```

class SubAgentInteractionPatterns:
    """主代理与子代理的五种交互模式"""

    @staticmethod
    async def delegate_and_wait(
        agent: "SubAgent", task: SubAgentTask, timeout: float = 60
    ) -> SubAgentResult:
        """
        模式 1: 委托-等待 (Delegate-and-Wait)
        最简单——主代理阻塞直到子代理完成。
        适用: 短任务(<10s)，结果直接影响后续决策。
        """
        return await asyncio.wait_for(agent.execute(task), timeout=timeout)

    @staticmethod
    async def delegate_and_poll(
        agent: "SubAgent", task: SubAgentTask, poll_interval: float = 1.0
    ) -> SubAgentResult:
        """
        模式 2: 委托-轮询 (Delegate-and-Poll)
        主代理继续执行其他工作，定期查询子代理状态。
        适用: 长任务(>10s)，主代理不希望阻塞。

        返回的是 Future——主代理可以在等待期间处理其他子任务。
        """
        future = asyncio.ensure_future(agent.execute(task))
        while not future.done():
            status = await agent.get_status()
            logger.debug("subagent.poll", agent_id=agent.spec.agent_id, status=status)
            # 主代理在此间隙做其他事
            await asyncio.sleep(poll_interval)
        return await future

    @staticmethod
    async def delegate_with_callback(
        agent: "SubAgent", task: SubAgentTask, callback_url: str
    ) -> None:
        """
        模式 3: 委托-回调 (Delegate-with-Callback)
        子代理完成时主动回调主代理。
        适用: 超长任务(>5min)，触发式通知。

        注意: 回调可能因网络问题丢失 → 需要兜底的轮询检查。
        """
        await agent.execute_async(task, callback_url=callback_url)

    @staticmethod
    async def delegate_streaming(
        agent: "SubAgent", task: SubAgentTask, on_chunk: Callable[[str], None]
    ) -> SubAgentResult:
        """
        模式 4: 流式反馈 (Streaming)
        子代理边执行边推送中间结果。
        适用: 生成报告、实时分析——用户想看到逐步进展。
        """
        return await agent.execute_streaming(task, on_chunk=on_chunk)

    @staticmethod
    async def negotiate_and_delegate(
        main_agent: "MainAgent", agent: "SubAgent", task: SubAgentTask
    ) -> SubAgentResult:
        """
        模式 5: 协商迭代 (Negotiate)
        主代理提出初步要求 → 子代理反馈不够/需要更多信息 → 主代理补充 → 执行。
        适用: 需求模糊的任务——子代理帮助主代理明确需求。
        """
        # 第一轮: 主代理发出初步需求
        feedback = await agent.request_clarification(task)
        if feedback.needs_clarification:
            # 子代理需要更多信息 → 主代理补充
            task.context.update(await main_agent.gather_missing_info(feedback.questions))
        return await agent.execute(task)
```

class SubAgentRegistry:
    """子代理注册表——所有可用子代理类型的目录"""

    def __init__(self):
        self._specs: dict[str, SubAgentSpec] = {}
        self._factories: dict[str, Callable[[SubAgentSpec, SubAgentTask], SubAgent]] = {}

    def register(self, spec: SubAgentSpec, factory: Callable = None):
        self._specs[spec.agent_id] = spec
        if factory:
            self._factories[spec.agent_id] = factory
        logger.info("subagent.registered", agent_id=spec.agent_id, type=spec.agent_type)

    def get_spec(self, agent_id: str) -> SubAgentSpec:
        if agent_id not in self._specs:
            raise SubAgentNotFoundError(f"子代理 '{agent_id}' 未注册。可用: {list(self._specs.keys())}")
        return self._specs[agent_id]

    def find_by_expertise(self, tags: list[str]) -> list[SubAgentSpec]:
        """按专业标签查找匹配的子代理"""
        matches = []
        for spec in self._specs.values():
            overlap = set(tags) & set(spec.expertise_tags)
            if overlap:
                matches.append((spec, len(overlap)))
        matches.sort(key=lambda x: x[1], reverse=True)
        return [spec for spec, _ in matches]

    def list_for_llm(self) -> list[dict]:
        """为 LLM 准备可用的子代理列表"""
        return [
            {
                "id": s.agent_id,
                "name": s.display_name,
                "description": s.description,
                "expertise": s.expertise_tags,
                "cost_profile": s.cost_profile,
            }
            for s in self._specs.values()

class SubAgentOrchestrator:
    """
    子代理编排器——主代理与子代理之间的"中间件"。

    职责边界：
      ✅ 按主代理的委托请求创建和调度子代理
      ✅ 管理并行执行、超时、重试
      ✅ 聚合子代理结果
      ✅ 监控子代理心跳（监督模式）
      ❌ 不决定"是否"委托（那是任务拆解的事）
      ❌ 不验证子代理结果（那是验证循环的事）
    """

    def __init__(
        self,
        registry: SubAgentRegistry,
        factory: SubAgentFactory,
        monitor: SubAgentMonitor,
        max_parallel: int = 10,
        default_timeout: float = 60,
    ):
        self.registry = registry
        self.factory = factory
        self.monitor = monitor
        self.max_parallel = max_parallel
        self.default_timeout = default_timeout
        self._semaphore = asyncio.Semaphore(max_parallel)

    async def delegate(
        self,
        agent_id: str,
        task: SubAgentTask,
        mode: str = "sync",
        timeout: Optional[float] = None,
        callback_url: Optional[str] = None,
        on_stream_chunk: Optional[Callable] = None,
    ) -> SubAgentResult:
        """委托单个任务给子代理"""
        spec = self.registry.get_spec(agent_id)
        timeout = timeout or spec.timeout_seconds

        async with self._semaphore:
            agent = await self.factory.create(spec, task)
            try:
                if mode == "async":
                    future = asyncio.ensure_future(agent.execute())
                    # 启动心跳监控
                    asyncio.create_task(self._monitor_heartbeat(agent, future))
                    result = await asyncio.wait_for(future, timeout=timeout)
                elif mode == "callback":
                    await agent.execute_async(task, callback_url=callback_url)
                    result = None  # 回调模式不阻塞等待
                elif mode == "streaming":
                    result = await agent.execute_streaming(task, on_chunk=on_stream_chunk)
                else:  # sync
                    result = await asyncio.wait_for(agent.execute(), timeout=timeout)
                return result
            except asyncio.TimeoutError:
                logger.error("orchestrator.timeout", agent_id=agent_id, timeout=timeout)
                return SubAgentResult(
                    agent_id=agent_id, task_id=task.task_id,
                    success=False, summary=f"超时 ({timeout}s)", errors=["TIMEOUT"],
                )
            finally:
                await self.factory.release(agent.instance_id, spec)

    async def delegate_parallel(
        self,
        tasks: list[tuple[str, SubAgentTask]],
        timeout: Optional[float] = None,
    ) -> list[SubAgentResult]:
        """并行委托多个子代理——全部完成后聚合结果"""
        logger.info("orchestrator.parallel_start", task_count=len(tasks))
        start = time.monotonic()

        coroutines = [
            self.delegate(agent_id, task, mode="sync", timeout=timeout)
            for agent_id, task in tasks
        ]
        results = await asyncio.gather(*coroutines, return_exceptions=True)

        # 将异常包装为失败结果
        wrapped = []
        for i, result in enumerate(results):
            if isinstance(result, Exception):
                wrapped.append(SubAgentResult(
                    agent_id=tasks[i][0], task_id=tasks[i][1].task_id,
                    success=False, summary=str(result), errors=[type(result).__name__],
                ))
            else:
                wrapped.append(result)

        elapsed = time.monotonic() - start
        success_count = sum(1 for r in wrapped if r.success)
        logger.info(
            "orchestrator.parallel_complete",
            total=len(tasks), success=success_count, elapsed=f"{elapsed:.1f}s",
        )
        return wrapped

    async def delegate_with_retry(
        self, agent_id: str, task: SubAgentTask, max_retries: int = 2
    ) -> SubAgentResult:
        """带重试的委托——失败后自动重试（使用幂等键防重复执行）"""
        spec = self.registry.get_spec(agent_id)
        task.idempotency_key = task.idempotency_key or f"{task.task_id}_{uuid4().hex[:8]}"

        for attempt in range(max_retries + 1):
            result = await self.delegate(agent_id, task)
            if result.success:
                return result

            if attempt < max_retries:
                delay = spec.base_delay_ms * (2 ** attempt) / 1000
                logger.warning("orchestrator.retry", agent_id=agent_id, attempt=attempt+1, delay=f"{delay:.1f}s")
                await asyncio.sleep(delay)

        return result

    async def _monitor_heartbeat(self, agent: SubAgent, future: asyncio.Future):
        """后台心跳监控——监督模式的核心"""
        while not future.done():
            await self.monitor.receive_heartbeat(agent.instance_id)
            await asyncio.sleep(SubAgentMonitor.HEARTBEAT_INTERVAL / 1000)
```

class ContextPassingStrategy:
    """
    决定主代理的哪些上下文需要传递给子代理。

    传递规则：
      - L1 必须传递: 全局约束（不要修改生产数据）、任务验收标准
      - L2 按需传递: 与子代理领域相关的用户偏好
      - L3 禁止传递: 主代理内部的推理过程、其他子代理的中间结果
      - 传递上限: ≤ 5000 tokens（防止子代理 context 一开始就过大）
    """

    @staticmethod
    def build_subagent_context(
        main_context: dict,
        subagent_expertise: list[str],
        task_description: str,
    ) -> dict:
        context = {
            "task": task_description,
            "global_constraints": main_context.get("constraints", []),
        }

        # 只传递与子代理领域相关的偏好
        if "user_preferences" in main_context:
            context["user_preferences"] = {
                k: v for k, v in main_context["user_preferences"].items()
                if any(tag in k.lower() for tag in subagent_expertise)
            }

        # Token 限制
        serialized = json.dumps(context, ensure_ascii=False)
        if len(serialized) > 20_000:  # ~5K tokens
            context["_trimmed"] = True
            context["_original_note"] = "上下文已裁剪——如需更多信息请向主代理请求"

        return context

            logger.warning("subagent.recovery_no_checkpoint", agent_id=crashed_agent_id)

            "duration_ms": result.metrics.get("duration_ms"),
            "tokens": result.metrics.get("tokens_consumed"),
            "cost": result.cost_estimate,
            "errors": result.errors,
        }
        await self._write_to_cold_storage(record)
```

## 9. 与其他模块的关系

| 关联模块 | 关系说明 | 生产示例 |
|---------|---------|---------|
| **01-四相循环** | 每个子代理内部运行独立的四相循环实例。主代理在 Phase 3 发起子代理调用，子代理完成后主代理继续 Phase 4 验证 | `sub_loop = FourPhaseLoop(...)` → Phase 3: `orchestrator.delegate(agent_id, task)` |
| **02-工具编排** | 子代理在编排器中是特殊的"超级工具"——注册表中的每个 `SubAgentSpec` 在编排时映射为 `ToolCategory.SUBAGENT` 类型 | `tool_node = ToolNode(tool_name=agent_id, category=SUBAGENT, timeout=300s)` |
| **03-进度跟踪** | 子代理创建独立进度树，通过 `parent_run_id` 挂载到主进度树。主代理可轮询 `/progress/{sub_run_id}` 查看子代理实时进度 | `sub_run_id = tracker.create_run(...)` → `main_node.metadata["sub_run_id"] = sub_run_id` |
| **04-上下文工程** | 主代理裁剪上下文后传递给子代理（≤5K tokens）。子代理拥有独立的 ContextManager 实例 | `sub_context = context_builder.build(task, main_context, expertise_tags)` |
| **05-任务拆解** | 拆解器识别出适合委托的子任务（需专门领域知识→标记为 `subagent_task`），并指定推荐的子代理类型 | `subtask.type = SUBAGENT_TASK; subtask.recommended_agent = "financial_analyst"` |
| **06-验证循环** | 主代理对子代理返回的 `SubAgentResult` 运行验证管线。不合格→要求子代理重试（带修正反馈）或切换到备用子代理类型 | `if not pipeline.verify(sub_result): orchestrator.delegate(fallback_agent_id, task_with_feedback)` |
| **08-GAN 三角色** | Generator 可生成多个子代理候选方案；Evaluator 评估各候选的适合度；Coordinator 选择最优子代理组合并调度执行 | Evaluator 打分: `{agent_id}_score=9` → Coordinator: `dispatch(agent_id)` |

## 10. 常见反模式与陷阱

### 10.1 过度嵌套

**症状**：子代理→孙代理→曾孙代理……深度 5 层，主代理 30 秒内发起 50 个子代理。调度开销超过实际工作，延迟爆炸到 3 分钟。

**事故**：某数据分析 Agent 将任务递归拆解→每层创建子代理→第 4 层时主代理 context 中存储了 200+ 个子代理引用，每次心跳检查耗时 12 秒。

**修复**：`MAX_DEPTH=3` 硬限制；超过深度降级为普通工具调用。`HAX_AGENTS_PER_LEVEL={1:20, 2:10, 3:5}`。

### 10.2 子代理间隐式依赖

**症状**：子代理 A 修改了 `/tmp/shared/data.csv`，子代理 B 同时读取——读到一半修改的文件，数据损坏。

**修复**：共享资源访问使用文件锁或读写锁。子代理间的数据流必须通过显式的 Blackboard 或消息队列——不能直接操作共享文件系统。

### 10.3 忽略子代理清理

**症状**：子代理执行完毕后临时容器未销毁，100 次调用后 50 个僵尸容器占用 8GB RAM。

**修复**：`finally` 块中强制 `cleanup()`。重量级子代理设置容器 TTL（5 分钟自动销毁）。编排器定期扫描僵尸实例并强制回收。

### 10.4 同步调用长耗时子代理

**症状**：用 `await delegate(financial_analyst, task)` 同步等待一个 10 分钟的财报分析。主代理在此期间完全阻塞。

**修复**：预估耗时 > 30s 的子代理使用 `mode="async"` + 轮询或 `mode="callback"`。主代理在等待期间处理其他独立子任务。

### 10.5 上下文过度共享

**症状**：主代理把自己的 100K token 完整 context 复制给每个子代理——4 个子代理 = 4 × 100K = 400K tokens 浪费。

**修复**：`ContextPassingStrategy.build_subagent_context()` 只传递 ≤5K tokens 的必要上下文。子代理需要更多信息时通过工具调用向主代理请求。

### 10.6 缺乏子代理幂等性

**症状**：子代理超时→主代理重试→子代理执行了两次 `send_email()`→用户收到重复邮件。

**修复**：关键操作子代理支持 `idempotency_key`。编排器在重试时传递相同的幂等键，子代理检查是否已执行过相同 key 的任务。

## 12. 总结与扩展阅读

### 核心要点

1. **子代理分治 = 横向扩展 + 专业分工 + 故障隔离**。不是让一个 Agent 更强，而是让多个 Agent 各司其职。

2. **隔离是核心价值**——上下文隔离防止 token 爆炸，变量隔离防止状态污染，文件隔离防止冲突，权限隔离防止越权。

3. **五种交互模式覆盖全场景**：同步短任务→delegate_and_wait，长任务→poll，超长任务→callback，实时反馈→streaming，模糊需求→negotiate。

4. **层级调度硬约束**：深度 ≤ 3，每层实例数 {1:20, 2:10, 3:5}。超过限制降级为工具调用。

5. **崩溃恢复基于进度跟踪**——子代理有独立的 progress.json（或 Redis checkpoint），crash 后可从断点恢复而非从头开始。

### 与现有框架对比

| 框架 | 子代理能力 | 差距 |
|------|---------|------|
| **LangGraph Subgraph** | 子图作为节点，共享 State | 缺少独立 ContextManager、缺少心跳监控 |
| **AutoGen** | 多 Agent 群聊，消息驱动 | 缺少层级调度、缺少正式的进度挂载 |
| **Coze Bot 调用 Bot** | 工作流中 `invoke_bot` 节点 | 缺少动态实例化、缺少监督模式 |
| **本方案** | 注册表+工厂+编排器+监控+恢复+审计 | 专为 Harness 生产级多 Agent 协作设计 |
